FCM): สำหรับส่งแจ้งเตือนไปยังอุปกรณ์ของผู้ใช้   Map Service (OpenStreetMap / Google Maps / Longdo Map): สำหรับปักหมุดพิกัดจุดนัดรับสินค้าภายใน สจล.
3.1 ระบบยืนยันตัวตนและจัดการบัญชี (Authentication & User Profile)
FR-1.1: รองรับการเข้าสู่ระบบด้วยอีเมลสถาบัน (@kmitl.ac.th) โดยระบบจะส่งรหัสผ่านใช้ครั้งเดียว (OTP) ผ่านบริการของ Google ไปยังอีเมลของผู้ใช้งานเพื่อยืนยันตัวตนก่อนเข้าใช้งานระบบ

FR-1.2: สามารถจัดการข้อมูลส่วนตัว (รูปโปรไฟล์, เบอร์โทรศัพท์, LINE ID, คณะ/สาขา, หอพัก/โซนที่สะดวกนัดรับ)

FR-1.3: แสดงสถานะยืนยันตัวตน (Verified Student/Staff Badge) บนโปรไฟล์เพื่อสร้างความน่าเชื่อถือ

3.2 ระบบจัดการสินค้าและรายการประกาศ (Product & Listing Management)
FR-2.1: ผู้ขายสามารถสร้าง แก้ไข และลบประกาศขายสินค้าได้

FR-2.2: รองรับการอัปโหลดรูปภาพสินค้าสูงสุด 5-10 รูป ต่อ 1 ประกาศ

FR-2.3: การระบุข้อมูลสินค้า: ชื่อสินค้า, รายละเอียด, ราคา, สภาพสินค้า (มือหนึ่ง/มือสอง %), หมวดหมู่, และจุดนัดรับใน KMITL (เช่น ตึก ECC, หอพักสถาบัน, โรงอาหารพระเทพ, คณะวิศวฯ)

FR-2.4: จัดการสถานะสินค้าได้ 3 สถานะ: พร้อมขาย (Available), ติดจอง (Reserved), และ ขายแล้ว (Sold Out)

3.3 ระบบค้นหาและกรองข้อมูล (Search & Filtering)
FR-3.1: ค้นหาสินค้าด้วยคีย์เวิร์ด (Keyword Search)

FR-3.2: กรองสินค้าตามหมวดหมู่ (เช่น หนังสือ/ชีทเรียน, ไอที/อิเล็กทรอนิกส์, เครื่องแต่งกาย/ชุดนักศึกษา, อุปกรณ์หอพัก)

FR-3.3: กรองตามช่วงราคา, สภาพสินค้า, และสถานที่นัดรับภายในสถาบัน

FR-3.4: จัดเรียงผลลัพธ์ตาม: มาใหม่ล่าสุด, ราคาต่ำ-สูง, ราคาสูง-ต่ำ

3.4 ระบบสื่อสารและนัดรับสินค้า (In-App Messaging & Deal Negotiation)
FR-4.1: ระบบแชตแบบเรียลไทม์ (Real-time Chat) ระหว่างผู้ซื้อและผู้ขาย

FR-4.2: สามารถส่งรูปภาพ พิกัดจุดนัดรับภายในสถาบัน และข้อความในแชตได้

3.5 ระบบให้คะแนนและรีวิว (Rating & Review)
FR-5.1: ผู้ซื้อสามารถให้คะแนนดาว (1-5 ดาว) และเขียนรีวิวผู้ขายได้หลังจบการซื้อขาย

FR-5.2: แสดงคะแนนเฉลี่ยความน่าเชื่อถือ (Trust Score / Rating) บนหน้าโปรไฟล์ของผู้ขาย

3.6 ระบบแจ้งเตือนและการรายงานความผิดปกติ (Notifications & Moderation)
FR-6.1: การแจ้งเตือน (Notification) เมื่อมีข้อความใหม่, มีคนกดจองสินค้า, หรือสินค้าที่บันทึกไว้มีการลดราคา

FR-6.2: ปุ่มรายงาน (Report) สินค้าผิดกฎหมาย, สินค้าต้องห้ามในสถาบัน (เช่น แอลกอฮอล์, บุหรี่ไฟฟ้า, ข้อสอบเก่าหลุด), หรือผู้ใช้ที่มีพฤติกรรมฉ้อโกง

FR-6.3: แผงควบคุมผู้ดูแลระบบ (Admin Dashboard) สำหรับตรวจสอบรายการที่ถูกรายงาน และจัดการลบโพสต์/แบนบัญชีผู้ใช้

4. ความต้องการที่ไม่ใช่ฟังก์ชัน (Non-Functional Requirements)
4.1 ความปลอดภัย (Security)
NFR-1.1: ข้อมูลรหัสผ่านต้องได้รับการ Hash ด้วยอัลกอริทึมที่ปลอดภัย (เช่น bcrypt) ก่อนบันทึกลงฐานข้อมูล

NFR-1.2: ใช้ HTTPS (TLS 1.3) ในการเชื่อมต่อรับ-ส่งข้อมูลทั้งหมดในระบบ

NFR-1.3: ใช้ JWT (JSON Web Token) หรือ Session Token ที่มีการกำหนดอายุในการยืนยันตัวตนสำหรับ API

4.2 ประสิทธิภาพและการรองรับการใช้งาน (Performance & Scalability)
NFR-2.1: หน้าเว็บ/แอปพลิเคชันต้องตอบสนองและแสดงผลภายในไม่เกิน 2 วินาที ในสภาวะโหลดปกติ

NFR-2.2: รองรับผู้ใช้งานพร้อมกัน (Concurrent Users) ได้อย่างน้อย 1,000 คน (โดยเฉพาะช่วงเปิดเทอมหรือรับน้อง)

NFR-2.3: รูปภาพสินค้าต้องได้รับการบีบอัด (Image Compression) อัตโนมัติก่อนจัดเก็บเพื่อประหยัดพื้นที่และโหลดได้เร็ว

4.3 การใช้งานและความยืดหยุ่น (Usability & Compatibility)
NFR-3.1: ออกแบบหน้าจอตามหลัก Responsive Design รองรับการใช้งานทั้งบนมือถือ แท็บเล็ต และคอมพิวเตอร์

NFR-3.2: ส่วนติดต่อผู้ใช้ (UI) มีขั้นตอนการลงขายสินค้าไม่เกิน 3 ขั้นตอน (Simple Onboarding)

4.4 ความพร้อมใช้งาน (Availability)
NFR-4.1: ระบบต้องมีความพร้อมใช้งาน (Uptime) ไม่ต่ำกว่า 99.5% ต่อเดือน

5. การเชื่อมต่อกับระบบภายนอก (System Integrations) (ปรับปรุงตาม FR-1.1)
Google Workspace / Gmail API (SMTP): สำหรับส่งรหัส OTP ยืนยันตัวตนไปยังอีเมลสถาบัน (@kmitl.ac.th)

Cloud Storage (เช่น AWS S3 / Cloudinary / Firebase Storage): สำหรับจัดเก็บรูปภาพสินค้าและรูปโปรไฟล์

Push Notification Service (เช่น Firebase Cloud Messaging - FCM): สำหรับส่งการแจ้งเตือนไปยังอุปกรณ์ของผู้ใช้

Map Service (เช่น Google Maps / Longdo Map): สำหรับปักหมุดพิกัดจุดนัดรับสินค้าภายในสถาบัน
